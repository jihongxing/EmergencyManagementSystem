# 用户、开通与数据权限

状态：`FROZEN`（首期边界）；试点字段级授权资料属于 `EXTERNAL INPUT`。来源：交接稿 4.5、4.6、4.8 节及后续最小实现方案的确认。

首期仅有四类日常业务角色；同一人可兼任**本方**管理员与执行角色。

| 角色 | 首期可做 | 不可推定 |
| --- | --- | --- |
| 单位管理员 | 管理本组织人员和负责的场所、对象；分配本组织的自检、整改、复查工作 | 不因账号而成为法定代表人或取得行政确认权 |
| 单位执行人员 | 在分配范围内执行自检、整改、复查，提交记录和证据 | 不管理其他成员、不形成行政检查记录 |
| 部门管理员 | 管理试点部门人员及本部门监管范围配置的操作权限 | 不得自行扩大法定职责；不必为每次临时抽检预建任务或派单 |
| 行政检查人员 | 核对身份、监管关系、事项及本次启动依据后扫码发起临时抽检、记录与复查 | 平台角色不等于执法资格；不得修改企业自检记录 |

## 首位管理员

试点实施人员凭线下确认的单位授权材料与部门指定材料，分别建立双方组织及首位管理员，记录材料来源与开通人。实施人员不是日常业务角色，也不代替单位或机关确认法定职责。此后管理员只添加本方成员；首位管理员更换经线下确认后办理。首期不做公众自助认领、电子证照集成或多级审批流。授权和撤销留痕，撤销后不可继续操作，历史记录保留原执行人。

## 可见性

单位仅能查看及操作本组织负责的场所与本组织记录；执行人员再受分配范围限制。部门仅能查看已确认归其监管场所内、在法定职责和共享范围内所需的自检、问题、整改与复查记录，并管理本部门独立的行政记录；检查人员写入受身份与适用事项限制。具体字段、证据共享范围需实施时核验；**系统能存储不等于该部门可以查看**。不创建首期市/省级账号或默认跨部门共享。自动绑定条件见 [03-site-identity](03-site-identity.md)。

订阅状态不授予本组织以外的数据权限，也不改变行政人员的身份核验、部门监管范围、事项或证据可见性；免费与订阅仅区分企业内部的操作便利，边界见 [01-product](01-product.md)。

## 操作核验

首位管理员仍凭线下材料开通；其后由本方管理员维护本方成员。后端对每次读取和写入核对当前身份、组织、角色及场所/对象分配范围，不能仅依赖客户端隐藏入口。行政操作另核对人员身份及资格材料、当前部门监管关系、适用事项和本次合法启动及程序依据；材料尚未核验时不能形成正式行政检查记录，具体行政材料仍由试点有权主体提供。撤权立即阻止后续操作，历史保留原执行人。

证据依所属记录及对应授权范围访问；不因部门与场所绑定就默认开放企业的全部字段或照片。试点字段/证据共享范围未核实时维持最小可见性，不推断额外查看权。具体凭据核验、字段规则和证据授权实现留待技术设计，但不得弱化上述逐次核验。
