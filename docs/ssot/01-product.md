# 产品定位与首期范围

状态：`FROZEN`。来源：交接稿 1、2、4.3、9 节；后续有关单县单部门、最小闭环及 2026-09-28 企业自愿订阅方案的明确批准。

V1 是面向辖区安全生产与应急管理的“自检 + 抽检 + 整改 + 行政检查”数字化共同底座。企业/物业是自检事实的主要生产者；有相应职责的行政部门在同一对象底座上开展抽检和监督，产生独立的行政事实。共享对象身份不等于共享所有数据或将两轨记录合并。

## 首期边界

- 从**单个县级辖区、单个有相应职责的监管部门**启动；企业/物业组织管理其负责的实际场所。县级监管视图用于其已授权范围。
- 市级、省级账号、乡镇/街道操作及跨部门操作首期不实现。组织、区划与监管关系留有扩展空间，但上级或其他部门不因层级而自动获得权限。
- 现场临时抽检由行政检查人员扫码发起，无需预建任务或派单；企业自检与行政记录各自独立。流程见 [05-workflows](05-workflows.md)。
- 不是单纯消防柜巡检 App、通用资产管理系统、纯企业安全管理 SaaS、二维码工具或大型城市治理平台。
- 不创设检查标准、周期、行政权力或处罚结论；不开发平台内处罚裁量或决定流程。权限和规则边界见 [02-authority](02-authority.md)。

多部门监管属于已冻结的**架构方向**，不是首期操作范围：一个组织/场所将来可能涉及多个部门，各部门的事项、权限与行政记录分别受其法定职责和数据共享规则约束；不能假设一个企业永远只有一个监管部门。

## 商业模式与免费边界

V1 以**企业/物业等组织自愿订阅**为主要商业方向；按签约组织而非场所、设施或二维码计费。首期支持免费使用和订阅后的企业工作台，不以行政部门推广、监管绑定或接受检查作为购买条件。月付 39 元、季付 108 元、年付 398 元是已批准的**试售价格**，用于验证真实支付与单位经济性，不构成已验证的盈利结论或永久固定价格。支付渠道、结算、开票、退款和续费的具体实现仍需设计；不能因此取消已批准的免费/订阅权益边界。

**免费版可独立完成企业轨闭环**：本组织场所、对象和人员管理，逐场所分配工作，扫码自检、上传证据、发现问题、提交整改及自主复查，逐场所查看完整记录和历史。必要的监管交互、依法需要的记录查看与提交始终不设订阅门槛；不按必要人员数、扫码数、自检次数、问题数、整改提交数或必要二维码数设置付费墙，也不因订阅到期删除、遮挡历史记录或中断监管配合。免费流程应正常可用，不人为降低操作质量来诱导付费。企业与行政双轨权限及记录边界仍按 [04-access](04-access.md) 与 [05-workflows](05-workflows.md)。

**首个付费卖点是企业工作台**：管理员可汇总本组织多个场所的自检、整改、复查待办及进度，并批量提醒或分配本组织工作；订阅购买的是跨场所协作和减少重复操作的便利，而非合规资格、行政检查权益、监管数据或更高权限。免费版仍可进入各场所逐项查看和操作。提醒只能依据已确认的适用规则或本组织自行设定的内部安排，不由平台创设法定检查周期。其他增强能力、政府专属服务合同及第三方生态不属于本次批准的首期功能；不得将政府端成本默认转嫁给订阅企业。历史县级采购设想留在[市场研究](../research/market-handover.md)，不再是 V1 的主要收入或产品准入前提。

订阅权益按**签约组织**由服务端判断；到期仅停止企业工作台的跨场所汇总和批量便利，逐场所操作、已有记录与监管必要交互继续可用。开通权益以服务端确认的支付结果为准，客户端显示付款成功不能单独作为授权依据。购买入口先按组织级 Web 购买流程设计，Flutter 仅读取权益；是否在 App 内提供购买及采用何种支付渠道，须按实际分发地区和应用商店规则核验后确定，不默认允许 App 引导站外支付。开票、退款和续费规则及具体支付集成仍待设计，不得由未确认的渠道规则倒推改变免费边界。
