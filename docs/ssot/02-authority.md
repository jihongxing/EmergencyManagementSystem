# 权威来源与平台边界

状态：`FROZEN`（原则）；具体地方材料属于 `EXTERNAL INPUT`。来源：交接稿 3、4.9、14 节。

| 权威 | 决定 | 平台职责 |
| --- | --- | --- |
| 对象 | 企业/物业申报、自更新并对真实性负责；法定登记/备案数据是外部权威来源；有职责的机关依法核验、纠正和确认 | 分开标记“单位申报”与“行政已确认”，保留来源和变更历史，不把企业输入伪装成行政确认 |
| 规则 | 检查事项来自法律法规、规章、国家/行业标准以及有权限的行政主体依法公布的事项 | 采集、结构化、版本化与呈现；保留事项、适用对象、依据、发布主体、版本、起止效力期、检查项及证据要求，不自行制定标准 |
| 周期与启动 | 企业自检以适用的法定最低要求为底线，结合企业自身制度；计划性行政检查依有权机关安排，临时检查依合法启动情形和程序 | 分开记录法定最低频次、企业频次和适用时的行政计划；首期扫码临时抽检不预建任务，但必须核对主体、人员、事项、启动情形与程序依据 |

检查历史绑定**实际执行时**的规则/模板版本，不因后续升级被改写。没有核实的事项或频次只能标“待确认”，不得显示为法律要求或合规判断；仅凭扫码、场所自动绑定或检查事项存在，都不能推定行政检查已合法启动。

规则内容、第一批检查单位或设施、当地频次、行政执法程序不是软件产品方制定的 SSOT。软件提供可配置、可追溯的承载能力；实际输入与核验门槛见[实施输入](../implementation/README.md)。首期现场路径见 [05-workflows](05-workflows.md)。
