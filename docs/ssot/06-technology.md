状态：`FROZEN`（选型方向和最小实现边界）。来源：交接稿 4.10 节、用户对技术形态及后续最小实现方案的批准。

- 监管部门桌面**响应式 Web 管理端**用于管理和查看。
- **一个 Flutter App 发布 Android/iOS，多个按身份隔离的工作区**承载单位自检与部门扫码抽检；共用客户端不合并双轨权限或记录。
- **模块化单体 Go 后端 + 关系数据库 + 证据文件存储**。
- 首期不采用微服务、复杂工作流引擎或跨部门数据交换。

## 首期实现边界

- 关系数据库选 PostgreSQL；证据文件与业务记录分开存储，由业务记录持有证据引用及授权信息。具体对象存储产品、部署拓扑和模块接口合同仍在对应工程任务确定。
- Flutter 现场操作首期要求在线提交；网络失败允许重试，不将未获服务端确认的操作显示为正式完成，也不承诺离线形成正式检查记录。离线采集与同步冲突处理不在首期范围。
- 以组织/成员、场所、检查对象与二维码映射历史、监管绑定及依据、规则版本、双轨记录、证据、问题与整改、订阅权益和审计历史为最小持久化概念。概念不是一概念一表；保留对象身份稳定性、版本引用和历史可追溯性。首期不因临时抽检预建行政计划或任务实体。
- 服务端维护组织级订阅权益并供 Web 和 Flutter 查询；权益仅控制企业工作台的跨场所汇总及批量便利，不替代身份/授权核验，免费流程仍独立可用。具体支付集成与权益更新机制在产品边界内设计，见 [01-product](01-product.md)。
- 组织购买页可以使用 Web，但不因此扩建完整的企业桌面管理端；监管部门的桌面 Web 管理端与企业购买入口按各自权限隔离。

不得因技术选型改变 [01-product](01-product.md) 的范围或 [02-authority](02-authority.md) 的权威边界。
