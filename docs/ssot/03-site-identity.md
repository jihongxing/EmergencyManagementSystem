# 场所、监管关系与对象身份

状态：`FROZEN`（产品行为）；具体地址与职责资料属于 `EXTERNAL INPUT`。来源：交接稿 4、4.1、4.2、4.4、4.7 节及后续最小实现方案的确认。

## 三层身份

企业/物业**组织**是责任与人员管理主体；**实际场所**是所在地归属及监管关系的基本单位；**检查对象**位于场所内。不得由组织注册地址推断所有场所的监管辖区。消防柜仅是示例，对象类型不得写死成消防设施，也不把软件扩成通用资产平台。

单位管理员申报负责的场所，记录名称、实际地址、责任关系和证明材料。场所“单位申报”与“行政已确认”是不同事实；自检不以行政确认作为前置条件。对象登记在场所下，关联对象类型、所属单位、位置、责任关系和生命周期状态。

## 自动匹配

首期在**实际地址明确归于试点县**且**明确命中经试点部门确认的监管范围规则**时，自动建立该部门与场所的监管关系，保存命中的依据及规则版本，不逐场所手工绑定。自动绑定不等于行政确认单位申报，也不赋予检查事项或启动行政任务。

地址不明、范围不明、重复场所或责任争议进入待处理列表；人工处理记录人员、理由、依据和时间；未确认时不可标记已绑定。地址或责任关系变更后重新匹配，旧关系与历史记录保留。地址解析方法及监管范围的权威资料由实施时核验，见[实施输入](../implementation/README.md)。

首期由单位填写**场所实际地址**，仅使用已核验的区划归属资料和试点部门监管范围作确定性匹配；唯一明确命中才自动绑定。不以地理位置近似、组织注册地址或未核验的地址推断结果代替明确命中。无法解析、出现多个候选、场所重复或规则冲突时不自动绑定，提交人工待处理；处理不能越过职责依据核验。地址、责任关系或监管范围规则变化时，重算**当前关系**并记录新旧依据、规则版本与生效时间，不追溯改写历史关系及检查记录。更具体的地址数据来源与解析实现取决于[实施输入](../implementation/README.md)。

## 二维码

对象生成稳定 Object ID 和二维码；二维码只映射对象身份，不永久绑定某张表。现场扫码后依据本次检查类型、适用事项及有效规则版本呈现内容。首期支持补打、停用和更换二维码并保留映射历史；扫码不产生行政授权。具体规则内容属于 [02-authority](02-authority.md) 的外部权威范围。
