# V1 平台与数据边界契约

状态：`DERIVED CONTRACT`。依据：[06-technology](../docs/ssot/06-technology.md)、[05-workflows](../docs/ssot/05-workflows.md)。本文件限定实现形态，不指定尚未选定的框架、存储供应商或接口路径。

## 平台

- `C05-01` 监管部门使用 Vue 3 + TypeScript + Vite 桌面响应式 Web 管理与查看；一个 Flutter App 发布 Android/iOS，按身份隔离工作区，承载单位自检与部门现场扫码抽检。组织购买页可使用 Web，但不因此引入完整的企业桌面管理端；购买入口与监管端按权限隔离。
- `C05-02` 后端采用 Go 标准库 net/http 模块化单体与显式 SQL，关系数据使用 PostgreSQL，本地开发采用 Podman/PostgreSQL 17；证据文件与业务记录分开存储并由业务记录持有引用及授权信息；首期不引入微服务、复杂工作流引擎或跨部门数据交换。开发配置不代表生产版本批准。
- `C05-03` 现场操作首期在线提交；网络失败允许重试，但未获服务端确认不能显示为正式完成或产生正式检查记录。首期不承诺离线正式记录或同步冲突处理。

## 最小持久化约束

- `C05-04` 持久化设计须容纳组织及成员、实际场所、对象与二维码映射历史、监管绑定及依据、规则版本、企业和行政独立记录、证据、问题与整改/复查、组织订阅权益及审计历史。这些是概念边界，不要求一概念一张表。
- `C05-05` 稳定对象身份、执行时规则版本与历史关系不可被当前状态覆盖。正式记录保存独立来源与关联；证据访问在服务端执行权限核验；付费权益检查不替代授权检查。
- `C05-06` 现场临时抽检无需预建行政计划、任务或派单实体。数据库驱动/迁移工具、对象存储、生产拓扑、正式应用标识/签名和模块接口须按对应任务确定并在编码前补充契约，不能由本契约臆定；既定 Web/Go 基线见平台条款。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| Flutter 提交后网络中断且无服务端确认 | 不显示正式完成；允许重试，结果以服务端状态为准 |
| 证据引用已知但用户没有所属记录授权 | 文件不能经应用访问 |
| 管理端或 App 查询已订阅组织 | 权益由服务端同一组织身份判断，不依赖客户端自报 |
| 行政人员现场扫码但无预建计划/任务 | 可进入依据核验，不因缺少预建任务直接阻断 |
