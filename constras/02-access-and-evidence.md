# 用户、权限与证据契约

状态：`DERIVED CONTRACT`。依据：[04-access](../docs/ssot/04-access.md)、[02-authority](../docs/ssot/02-authority.md)；外部依赖：[实施输入](../docs/implementation/README.md)。

## 不变量

- `C02-01` 仅有单位管理员、单位执行人员、部门管理员、行政检查人员四类日常角色。同一人可兼任本方管理员及执行角色，但不得因平台角色获得法定代表人身份或行政执法资格。
- `C02-02` 试点实施人员凭线下核验材料分别建立双方组织与首位管理员，留存材料来源及开通人；实施人员不充当日常业务角色。首位管理员更换仍需线下确认；不开放公众自助认领。
- `C02-03` 本方管理员只能增删本方成员；授权和撤销留痕，撤销后后续访问应被拒绝，历史记录保留原执行人。
- `C02-04` 每次读取和写入均由服务端核对当前身份、组织、角色、场所与对象分配范围；客户端隐藏入口不是授权控制。单位只访问本组织负责的场所与本组织记录，执行人员再受分配范围限制。
- `C02-05` 部门只可在已确认监管场所、法定职责及已核验的共享范围内读取所需企业数据，并操作本部门独立的行政记录。行政写入另核对人员身份及资格、适用事项和本次启动及程序依据；未核验时不得形成正式行政记录。
- `C02-06` 证据的读取以所属记录及相应授权为前提；部门与场所绑定不自动开放企业全部字段或照片。字段/证据共享范围未核验时按最小可见性处理，不推断额外查看权。
- `C02-07` 订阅状态仅影响本组织企业工作台便利功能，不扩大组织、部门、人员或证据权限。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 执行人员请求本组织另一未分配场所的记录或证据 | 服务端拒绝 |
| 单位管理员尝试管理别的组织成员 | 服务端拒绝 |
| 行政人员扫码但身份、资格、事项或启动依据未核验 | 不创建正式行政记录 |
| 部门已绑定场所，但照片共享范围未获确认 | 不因绑定而开放企业照片 |
| 成员权限被撤销后重放原请求 | 后续读取和写入均拒绝；历史署名不变 |
| 订阅组织尝试读取另一组织的工作台数据 | 服务端拒绝，不能借权益越权 |
