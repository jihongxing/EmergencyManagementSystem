# P0-03 数据库基础契约

状态：`DERIVED CONTRACT`。依据：[技术 SSOT](../../docs/ssot/06-technology.md)、[平台契约](../05-platform.md)。只交付 PostgreSQL 连接、就绪与迁移基础，不创建业务表或行政数据。

- 使用 pgx database/sql 适配与 Goose SQL 迁移，版本由 go.mod/go.sum 固定；这是 P0-03 工程实现，不确定生产供应商。
- `DATABASE_URL` 必填；缺失或格式无效时拒绝启动，日志不得输出连接串/密码。连接暂时失败时存活探针仍返回 200，就绪返回 503；恢复后下一次就绪请求重新检查。
- `GET /health/ready` 在 2 秒上下文期限内检查数据库连通性及迁移版本：达到本程序要求的版本才返回 200 `{"status":"ready"}`，否则返回 503 `{"status":"not_ready"}`。不返回数据库错误细节。
- 存活与就绪均不证明权限、行政依据、证据服务或完整业务可用。
- 独立 `go run ./cmd/migrate` 执行向前迁移，API 启动不自动改库。迁移按版本逐步建立平台基础及已批准业务模块表；就绪检查以当前程序要求的迁移版本为准。
- SQL 迁移默认事务执行；重复运行无变化；迁移失败应回滚该文件，不将失败版本标记为成功。不提供自动生产回滚命令。
- Podman 项目名独立，端口仅绑定本机回环；命名卷保留。集成测试须显式提供 `TEST_DATABASE_URL`，只用于专用测试库，不自动清空或销毁卷。

验收：空库就绪 503 -> 显式迁移 -> 就绪 200；重复迁移；事务失败无残留；不可达数据库就绪 503 且存活 200；停止/重启本项目数据库后迁移元数据仍存在且就绪恢复。
