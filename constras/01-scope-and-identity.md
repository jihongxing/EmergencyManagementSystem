# V1 范围与身份契约

状态：`DERIVED CONTRACT`。依据：[01-product](../docs/ssot/01-product.md)、[03-site-identity](../docs/ssot/03-site-identity.md)；外部依赖：[实施输入](../docs/implementation/README.md)。

## 不变量

- `C01-01` V1 日常操作仅覆盖单县、单有相应职责的监管部门及其已授权范围；不得自动开通市、省、乡镇/街道账号或跨部门操作。数据结构可保留未来多部门关系，但不得据层级推导权限。
- `C01-02` 组织承载责任与人员；实际场所承载所在地与监管关系；对象属于场所。组织注册地址不能代替场所实际地址；对象类型不写死为消防设施。
- `C01-03` 单位管理员申报场所的名称、实际地址、责任关系和证明材料；单位申报与行政已确认分别标识来源和历史。未行政确认不阻止本组织自检，也不得显示为行政已确认。
- `C01-04` 对象具有稳定身份；二维码只解析到对象，不固化检查表。补打、停用或更换二维码后保留映射历史；二维码本身不赋予行政检查权限。
- `C01-05` 当前监管绑定仅在实际地址明确归于试点县，且唯一命中经试点部门确认的监管范围规则时自动建立；记录地址归属及监管规则的依据、版本与生效信息。自动绑定不等于确认单位申报，也不等于确认检查启动依据。
- `C01-06` 地址无法解析、范围未核验、多个候选、重复场所、责任争议或规则冲突均不得自动标记已绑定；进入人工待处理。人工处理须记录操作人、理由、依据和时间，不能绕过部门职责核验。
- `C01-07` 地址、责任关系或监管范围变化仅重算当前绑定并留存新旧关系及依据；历史记录不回写为新的归属。不得使用近似坐标或组织注册地址假装确定性命中。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 单位申报未获行政确认的场所，并在本组织范围自检 | 可继续自检；场所仍标记为单位申报 |
| 已核验地址在试点县内，唯一命中已确认的部门范围 | 自动建立当前绑定并保存命中依据及版本 |
| 地址模糊、范围未核验或命中多个候选 | 无已确认绑定；进入待处理，不能由扫码提升状态 |
| 原绑定后修改地址或监管规则 | 重新判定当前关系；旧关系和旧检查记录保持原样 |
| 对象二维码停用或更换 | 旧映射可追溯，当前扫码不能将停用码当作有效检查入口 |
