# 身份与最小组织模块契约

状态：`MODULE CONTRACT`。任务：`P1-01`。依据：[用户与权限 SSOT](../../docs/ssot/04-access.md)、[场所与身份 SSOT](../../docs/ssot/03-site-identity.md)、[C02 权限契约](../02-access-and-evidence.md)、[C05 平台契约](../05-platform.md)。

本契约只定义身份、组织、成员和会话的最小软件边界，不定义行政资格、检查事项、辖区规则或法定材料内容。正式实施输入仍由有权主体提供并核验；缺失时只能进入待确认或拒绝状态。

## 首期范围

- 组织类型只有 `enterprise`（企业/物业等单位组织）和 `department`（试点监管部门组织）。
- 日常角色只有 `enterprise_admin`、`enterprise_executor`、`department_admin`、`inspector`。
- 账号不开放公众注册。组织和首位管理员由受控实施入口依据线下核验材料建立；实施人员不是日常角色。
- 本方管理员只能管理本组织成员。单位管理员可兼任单位执行人员，部门管理员可兼任行政检查人员；不得跨组织混合角色。
- 登录凭据采用组织内唯一登录标识加密码。密码只保存不可逆哈希；接口不回显密码或密码哈希。
- Web 使用服务端会话 Cookie；Flutter 使用短时访问凭据和可撤销刷新凭据。令牌或会话不替代每次请求的当前成员状态核验。
- 成员生命周期为 `pending`、`active`、`suspended`、`revoked`。只有 `active` 成员可登录和执行日常操作；撤销后拒绝后续请求，历史记录保留原执行人。
- 密码恢复采用不泄露账号存在性的请求/确认两步流程；恢复令牌一次性、短时有效并服务端可撤销。
- 首位管理员更换是受控实施操作，必须记录材料来源、核验状态、操作人和时间；普通管理员接口不得绕过该流程。

## 数据约束

| 对象 | 必要约束 |
| --- | --- |
| 组织 | 稳定 ID、组织类型、名称、状态、创建来源与创建时间；组织类型不能被客户端写入为未知值 |
| 成员 | 稳定 ID、用户 ID、组织 ID、登录标识、状态、角色集合、创建/更新时间；同一组织内登录标识唯一 |
| 角色 | 只能使用与组织类型匹配的角色；同一角色不得重复；不得混用单位与部门角色 |
| 会话 | 服务端生成的不可预测 ID、成员 ID、客户端类型、创建/过期/撤销时间；撤销后不可恢复使用 |
| 审计 | 成员授权、角色变更、状态变更、首位管理员变更和会话撤销必须留痕；不得记录密码、刷新凭据原文或敏感恢复令牌 |

## 接口行为

接口路径、请求响应和状态码见 [identity.openapi.json](identity.openapi.json)。数据形状和枚举见 [data.schema.json](data.schema.json)，生命周期正反案例见 [lifecycle.json](lifecycle.json)。

所有受保护接口必须从服务端会话/访问凭据解析当前成员，并重新读取成员状态、组织、角色和目标范围。客户端声明的角色、组织或工作区不能授予权限。

密码登录失败、未知登录标识、暂停/撤销成员和无效恢复请求统一使用不泄露账号存在性的错误表现。登录成功后不得因为客户端选择工作区而扩大服务端权限。

## 错误和状态边界

| 情形 | 契约结果 |
| --- | --- |
| 缺少凭据或凭据无效 | `401`，统一 `authentication_required` |
| 成员非 `active` | `403`，`member_inactive` |
| 角色或组织范围不符 | `403`，`authorization_denied` |
| 请求违反当前成员/组织数据约束 | `409` 或 `422`，按接口定义返回 |
| 登录/恢复请求无法确认账号 | 使用统一结果，不暴露账号是否存在 |
| 首位管理员材料缺失或未核验 | 受控开通/更换拒绝，不形成已确认组织或管理员事实 |

## 不在本契约内

- 公众注册、电子证照集成、短信/邮箱供应商、支付、行政资格认定、多级组织、跨部门授权。
- 场所、对象、二维码、监管绑定和行政检查记录接口。
- 生产密钥托管、部署拓扑和最终分发渠道；这些在相应任务中另行确定。
