# 身份模块第一单元

状态：`DERIVED CONTRACT`。依据：[权限 SSOT](../../docs/ssot/04-access.md) 与 [C02-01 至 C02-04](../02-access-and-evidence.md)。

本单元已扩展为 P1-01/P1-02/P1-03 身份/组织模块契约集合：`module.md` 定义边界，`data.schema.json` 定义组织、成员、会话和密码恢复数据形状，`lifecycle.json` 定义生命周期正反案例，`bootstrap.md` 与 `bootstrap.json` 定义组织及首位管理员受控开通，`session.md` 定义会话与逐次身份校验，`identity.openapi.json` 定义最小接口面。它们仍然不表示实施人员认证、完整成员管理或移动端工作区已经实现。

现有 `authorization.json` 仍仅描述服务端内部的当前成员校验和“管理本方普通成员”的准入判定，不实现登录、数据库、邀请接口、首位管理员开通/更换或行政资格核验。账号当前状态必须由未来的服务端数据层读取，不接受客户端角色声明作为事实。

P1-01 的凭据设计采用组织内唯一登录标识加密码；Web 会话使用服务端 Cookie，Flutter 使用短时访问凭据和可撤销刷新凭据。恢复渠道、密码策略、密钥托管和正式部署配置仍需在实现与试点安全要求中核验，不由本契约伪造为已完成。

输入为当前成员的用户 ID、组织 ID、组织类型、启用状态及角色集合，目标为组织 ID。单位组织只接受单位管理员/执行人员角色，部门只接受部门管理员/检查人员角色；未知类型、未知角色、空角色、空 ID、重复角色、跨组织请求及停用成员均拒绝。管理员兼任本方执行角色有效；执行人员不能仅靠执行角色管理成员。该判断只是普通成员管理的必要条件，不授权首位管理员更换或授予行政资格。

输出为稳定的准入码，详见 [机器案例](authorization.json)。代码测试必须解析这些案例并验证结果。P1-01 的生命周期案例由统一机器契约门禁按 `identity-lifecycle.schema.json` 校验，OpenAPI 由同一门禁解析；校验通过不意味着已取得身份凭据、场所授权或行政操作权限。内部授权函数只能在每次请求获取当前服务端成员状态后调用，不能缓存旧权限来绕过撤权。
