# 规则、自检与行政记录契约

状态：`DERIVED CONTRACT`。依据：[02-authority](../docs/ssot/02-authority.md)、[05-workflows](../docs/ssot/05-workflows.md)、[03-site-identity](../docs/ssot/03-site-identity.md)；外部依赖：[实施输入](../docs/implementation/README.md)。

## 规则与版本

- `C03-01` 检查事项、适用对象、规则和证据要求来自经核验的有权来源；保留依据、发布/确认主体、版本及效力期。企业自设内部安排与法定最低要求分别标识，不由平台创设法定事项、检查周期或合规结论。
- `C03-02` 规则或频次尚未核实时只能标记待确认，不能显示为法定义务、行政确认或检查合格；正式行政检查还必须核验本次合法启动情形及程序依据。配置事项、扫码及自动绑定均不能单独替代这些核验。
- `C03-03` 每条执行记录须关联执行人、执行时间、当时的场所与对象身份及有效规则/事项版本，并标识企业或行政来源。后续规则、对象或二维码关系变化不得覆盖当时事实；纠错留审计。

## 企业轨

- `C03-04` 本组织在有权限的场所登记对象、扫码自检、记录结果、发现问题、提交整改证据并自主复查；问题、证据和复查关联来源记录及对象。没有核验的法定规则不得被界面伪装为已确认规则；企业自检结果不能变为行政检查合格结论。
- `C03-05` 免费与订阅组织都能逐场所完成以上闭环、查看完整本组织历史及提交必要监管资料；无付费限制的必要人员、扫码、自检、问题、整改和二维码操作。

## 行政轨

- `C03-06` 已取得并核验相关外部依据后，检查人员在现场扫码识别对象及场所，核对本人身份、部门监管关系、适用事项、本次启动和程序依据后，才可发起临时抽检并形成独立行政记录、证据、整改要求及后续复查记录。首期不要求逐次预建任务、计划或派单。
- `C03-07` 无法确认任一必要依据时，不得创建或标识正式行政检查记录；测试路径不得以模拟材料冒充正式记录。行政记录不得修改、覆盖企业记录；企业记录亦不得修改行政记录。
- `C03-08` 证据只在获授权范围内关联和读取；处罚首期只关联平台外形成的文书，不提供平台内处罚裁量、决定或执行流程，处罚也不是每次抽检的必经步骤。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 企业记录问题、上传整改证据并自主复查 | 留存独立企业来源及记录间关联；不产生行政检查合格结论 |
| 规则升级或对象二维码变更后查看既有检查 | 保留执行时版本、对象与记录来源，不覆盖历史 |
| 行政人员仅有有效二维码，缺少本次启动或人员程序依据 | 不形成正式行政检查记录 |
| 行政人员具备全部已核验条件并现场扫码 | 可形成独立行政记录，无需预建任务 |
| 任一轨尝试直接修改另一轨历史记录 | 拒绝，纠错只能按留痕机制处理 |
